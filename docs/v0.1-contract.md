# Proofmarks V0.1 product contract

Status: release-candidate freeze, 2026-08-30.

This document freezes the intended public contract for `proofmarks@0.1.0`. It does not freeze internal workspace packages, scene geometry, test attributes, or the Suggesting demo.

## Semantic operations

V0.1 contains exactly eight notation-neutral operations:

1. `delete` — one non-empty `text-range`;
2. `insert` — one `text-point` and non-empty `content`;
3. `replace` — one non-empty `text-range` and non-empty `replacement`;
4. `transpose` — two ordered, non-overlapping `text-range` operands;
5. `move` — one source `text-range` and an outside destination `text-point`;
6. `increase-spacing` — one boundary `text-point`;
7. `decrease-spacing` — one non-empty range containing existing source whitespace only;
8. `cancel-correction` — one stable reference to another correction ID.

Correction data are plain JSON-serializable objects. Text offsets count UTF-16 code units over flattened source `textContent`; semantic objects contain no DOM nodes, browser geometry, notation symbols, or CSS values.

## Notation systems

- JIS — reference-based JIS Z 8208 reconstruction;
- GB — reference-based GB/T 14706 reconstruction;
- CNS 3927 — Taiwan-specific reconstruction with source-backed mappings and explicit unverified cells;
- KS — source-backed Korean reconstruction with explicit evidence limits;
- English · US — traditional US publishing conventions, not one national standard.

## Appearance

- `technical` — default, canonical inspection treatment;
- `editorial` — deterministic red-pencil treatment with the same semantic and placement result.

`showProofmarks` controls only SVG visibility and defaults to `true`.

`animate: false` disables editorial write-on motion for still proofs, many
instances, and exporters that copy computed styles.
The vanilla instance has `replay()` for an explicit replay. `onRender` reports
fidelity, fallback count, and layout time. `onIssue` also reports invalid React
corrections, insufficient annotation room (with `collisions`), and right-to-left
roots (`unverified-direction`). React accepts headings, `pre`,
`code`, `td`, `th`, and `label` as roots. The overlay remains inside the root;
`getSourceText(root)` returns the source without SVG labels for UTF-16 offsets.

`markStyle` is the constrained presentation API shared by React and vanilla:

```ts
{ ink?: string; strokeScale?: number; opacity?: number; labelInk?: string }
```

It preserves notation geometry and layout. Stroke scale is clamped to `0.75–1.5`, opacity to `0–1`, and invalid CSS colors or numbers report `onIssue` before falling back safely. V0.1 does not expose arbitrary SVG, path geometry, offsets, transforms, or per-mark override hooks.

## Writing-mode capability

Horizontal operation coverage exists across the built-in packs, subject to the evidence and scale limits in [the capability matrix](notation-capability-matrix.md). JIS has direct vertical constructions for delete, insert, replace, transpose, and cancel-correction; its other vertical operations use generic fallback. GB and KS vertical operations use generic fallback. CNS 3927 has a direct vertical insertion form but keeps unaudited vertical cells explicit. English · US vertical writing is unsupported and emits no fabricated mark.

## Explicit non-goals and verified limitations

- no public notation-pack authoring SDK;
- no editor, comments, collaboration, persistence, AI proofreading, or export API;
- no guarantee for portals, CSS generated content, hidden duplicate text, or arbitrary components that rewrite source DOM independently;
- no grapheme-index offsets; callers own UTF-16 ranges;
- wrapped and multi-rect targets may use generic fallback;
- right-to-left text is unverified for every pack;
- source text remains browser-native and selectable; overlays are presentation only;
- real OS IME, real Safari, and assistive-technology sessions are not claimed by automated browser results.

See [known limitations](known-limitations-v0.1.md) for the operational detail.
